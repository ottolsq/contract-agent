# 目标与范围

## 问题

科技公司的合同审查要人翻法条：劳动人事、对外商业、技术合同各有不同的适用规则，风险点分散、引用难核。直接问通用大模型有两个硬伤——会编造法条，且给不出可追溯的出处。审查一条合同条款，人工成本高且不稳定。

## 用户

- 科技公司的法务、HR 与业务负责人：对内劳动人事合同、对外商业与技术合同
- 演示与评测场景：需要可复现的指标（召回率、引用准确率、分类准确率）而不是「看起来对」

## 目标

- 基于法规知识库做检索，答案里的每一条引用都能回溯到具体条文（L1 校验）
- 整份合同端到端审查：分类 → 拆分条款 → 逐条判定风险 → 汇总报告
- 可评测：检索召回、引用准确率、分类准确率都有脚本与门禁

## 非目标

只列最常被误解的四条，完整边界见 README 的「不做什么（边界）」：

- 不是通用法律助手，不做刑事、诉讼、婚姻继承、仲裁代理
- 不生成合同，只审查与提示风险
- 不构成法律意见：输出仅供参考，签署前须法务或律师复核
- 不做多租户、权限、审计等企业级能力；当前是演示原型

## 成功标准

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 检索召回 | 门禁 0.6，当前 0.8293（micro，混合检索，2026-11-21） | `uv run python scripts/evaluate.py --mode retrieval --fail-under 0.6` |
| 引用准确 | L1 基线 0.9477 | `--mode full --fail-under-l1 0.9` |
| 分类准确 | 0.90，降级率 10%，域过滤丢失 0/30 | `--mode classify` |
| 测试 | 225 个用例全绿 | `uv run pytest` |

## 约束

- Python 3.12，用 `uv` 管理依赖与运行
- 需要可用的 OpenAI 兼容模型服务（`LLM_API_KEY`）
- 向量库是本地 Chroma（`data/chroma`，不入库）
- 法规只用官方公开来源；演示合同只用公开示范文本
